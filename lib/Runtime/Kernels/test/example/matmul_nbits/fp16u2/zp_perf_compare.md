# MatMulNBits u2 vs u4 — with zero_points performance

Steady-state performance of the **packed zero_points real-model path** for 2-bit (u2) weights, compared head-to-head against 4-bit (u4) **with zero_points** on identical (M, K, N, group_size) shapes. Generated by `bench_zp_perf.py`.

The `u2(pkd-zp)` number mirrors the runtime: the ONNX-packed zero_points are unpacked to one-byte-per-group **once** (excluded from timing, as the wrapper caches per pointer), then the GEMM is timed with `zero_points`=packed blob + `pre_unpacked_zp_u8`=unpacked buffer. GFLOP/s uses the same FLOP count for all kernels (fair throughput metric); GB/s reflects actual bytes moved (u4 moves more weight bytes). `speed` is the u4/u2 median-time ratio (>1 means u2 is faster).

- GPU: AMD Radeon 8060S (gfx1151)
- All shapes run WITH zero_points (asymmetric quantization).
- `unpack` = packed -> one-byte-per-group byte-exact check; `verify` = full GEMM vs FP32 NumPy reference.

#### Notes

- **Decode (M=1)** is memory-bound: reducing weight bytes directly reduces latency, so u2 tends to beat u4 here.
- **Prefill (M=128/512)** hits the WMMA path and is compute-bound: all bit-widths saturate the tensor cores, so throughput is ~parity (the low-bit weight-size win shows up as GB/s headroom, not GFLOP/s).
