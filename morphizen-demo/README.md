# MorphiZen Demo

An example of how to add your own implementation in MorphiZen.

The `demo` contains a full implementation of the MorphiZen flow, encompassing both `level-1-pass-relu-dq`and `custom-op-relu-dq`.

---

## Build Instructions

### Build ONNXRuntime

To build ONNX Runtime, follow the [official documentation](https://onnxruntime.ai/docs/build/inferencing.html).

It is recommended to use Git Bash. The commands below have only been tested in Git Bash. They might also work in other shells with slight modifications.


#### Dwownload onnxruntime

```bash
# Create a workspace directory
mkdir workspace
cd workspace

# Clone the ONNX Runtime repository
git clone https://github.com/Microsoft/onnxruntime.git
cd onnxruntime
```


#### Build ONNX Runtime

```bash
./build.bat --use_vitisai --config Debug --build_shared_lib --parallel --compile_no_warning_as_error --skip_submodule_sync --build_dir ../build/onnxruntime   --skip_tests  --cmake_extra_defines CMAKE_INSTALL_PREFIX=$PWD/../local
cmake --build ../build/onnxruntime/Debug/ --target install
```

This script is used to build the ONNX Runtime project with specific configurations and options. Below is a breakdown of the command-line arguments used:

- `--use_vitisai`: Enables the use of Vitis AI for acceleration.
- `--config Debug`: Specifies the build configuration as Debug.
- `--build_shared_lib`: Builds the project as a shared library.
- `--parallel`: Enables parallel compilation for faster build times.
- `--compile_no_warning_as_error`: Prevents warnings from being treated as errors during compilation.
- `--skip_submodule_sync`: Skips the synchronization of submodules, assuming they are already up-to-date.
- `--build_dir ../build/onnxruntime`: Specifies the directory where the build artifacts will be generated.
- `--skip_tests`: Skips the execution of tests after the build process.
- `--cmake_extra_defines CMAKE_INSTALL_PREFIX=$PWD/../local`: Passes additional CMake definitions, setting the installation prefix to a local directory relative to the current working directory.

#### Build morphizen-demo

#### Download morphizen and morphizen-demo

```bash
cd workspace
git clone git@gitenterprise.xilinx.com:VitisAI/morphizen-demo.git
git clone git@gitenterprise.xilinx.com:VitisAI/MorphiZen.git --recursive
```

#### Configure and build

```bash
cd morphizen-demo
cmake -DBUILD_SHARED_LIBS=OFF -B ../build/morphizen-demo -S . -DCMAKE_INSTALL_PREFIX=$PWD/../local
cmake --build ../build/morphizen-demo --config Debug --target install
```

This script demonstrates the steps to configure, build, and install the `morphizen-demo` project.

Steps:
 1. Navigate to the `morphizen-demo` directory.
 2. Run the `cmake` command to configure the project specify the build directory (`../build/morphizen-demo`),
    and set the installation prefix to a local directory.
 3. Build the project in Debug configuration and install the resulting binaries to the specified installation directory.


## Demo Design

In this demo project, we will demonstrate how to fuse the `relu->dq` sequence into a subgraph and implement a custom operator kernel to support it effectively.


### Generate a Pattern

`relu_dq.json` has already been generated. If this step is not relevant to your needs, you can safely skip it.

Before proceeding, ensure you have built a standalone `MorphiZen` by following the instructions in `MorphiZen/README.md` or you have built `morphizen-demo` . Once completed, you should have access to tools such as `morphizen-pattern-gen` and `morphizen-graph-opt`. Additionally, ensure you have the sample model `pt_resnet50.onnx` available.

```bash
cd morphizen-demo
../local/bin/morphizen-pattern-gen -f ../build/morphizen-demo/_deps/morphizen-build/unit-test/pt_resnet50.onnx -i 127 -o 131 -m ./patterns/relu_dq.mmd -j ./patterns/relu_dq.json
```

### Test the Pattern

To test the pattern, you will need to port `morphizen-onnx-grep` to your environment. This tool is essential for verifying the correctness of the generated pattern and ensuring it aligns with the expected subgraph structure.

Steps to port and use `morphizen-onnx-grep`.

Before proceeding, ensure you have built a standalone `MorphiZen` by following the instructions in `MorphiZen/README.md` or you have built `morphizen-demo` . Once completed, you should have access to `morphizen-onnx-grep` which a test pattern tool. And the test pattern json file (eg. `relu_dq.json` which generated by `morphizen-pattern-gen`) and the test model `pt_resnet50.onnx` has already.

Here is a sample for test `relu_dq.json`
```bash
cd morphizen-demo
../local/bin/morphizen-onnx-grep -f ../build/morphizen-demo/_deps/morphizen-build/unit-test/pt_resnet50.onnx -p ./patterns/relu_dq.json -n 131
```
`-f` <onnx_model> : onnx model file<br/>
`-p` <pattern_file> :  pattern file, can be json or python file <br/>
`-n` <node_arg> : node_arg name to trace ， checks whether a node matches pattern. <br/>
     If the `-n` option is omitted, the entire network will be traversed, and all nodes matching the pattern within the network will be matched. <br/>
`-v` verbose mode <br/>

### Test the End-to-End Flow

To test the entire flow, you can use `test_onnx_runner` or your own Python script.


```bash
cd morphizen-demo
env XLNX_ONNX_EP_VERBOSE=2 DEBUG_LOG_LEVEL=info ../local/bin/test_onnx_runner.exe ../build/morphizen-demo/_deps/morphizen-build/unit-test/pt_resnet50.onnx
```

Optional Environment Variables

To assist in debugging and enhance logging during execution, you can configure the following environment variables:

- **`XLNX_ONNX_EP_VERBOSE`**: Enables verbose logging for the Xilinx ONNX Execution Provider, providing detailed insights into its operations.
- **`DEBUG_LOG_LEVEL`**: Sets the debug log level to control the granularity of logging output for troubleshooting purposes.

Adjust these variables as needed to streamline the debugging process.
